## 1. 定位

在 M2 上运行一个本地 GTK4 视频播放器，用两件事体现板卡能力：

1. **VPU 硬解**：H.264/H.265 4K/1080p 硬解码，CPU 占用低、播放不丢帧。
2. **NPU + GPU 实时美颜**：自动检测画面中的人脸，在脸部区域做磨皮与美白，
   并支持一键原图/美颜对比。

IINA 和 ExoPlayer 不是代码依赖，而是体验与架构参考：IINA 代表桌面播放器的
交互完整度，ExoPlayer 代表“解码管线 + 可插拔渲染”的分层方式；M2 版本把二者
在 RK3576 上落到 GStreamer（VPU） + RKNN（NPU） + OpenGL ES（GPU）的组合。

## 2. 目标用户与场景

| 用户 | 场景 | 关注点 |
|------|------|--------|
| 方案演示 | 展会/客户现场播放人像视频，展示“人物自动美颜” | 效果肉眼可见、对比直接、操作简单 |

## 4. 非目标

- 4K 输出不是硬指标（P4 已确认）：DSI 屏为 1280×800，1080p 播放即满足验收，4K 仅作可选加分项。
- 不做 DRM/版权内容解密，不做播放器商店级格式大全（以板端 GStreamer 插件为准）。
- 不做视频编辑/导出工具（E3 仅为截图/导出当前帧）。
- 不做多用户、账号体系或云端媒体库。

## 5. 验收标准

沿用设计文档的 A1–A6，逐条对应验证手段：

| ID | 标准 | 验证方式 |
|----|------|---------|
| A1 | 1080p30 H.264/H.265 硬解不丢帧，CPU < 30%；4K30 H.265 流畅为可选加分项（4K 不作硬指标） | `top`/fpsdisplaysink 统计 + 信息面板 |
| A2 | 1080p30 开美颜时 ≥ 25fps（显示 1280×800） | 信息面板 + 录制帧率日志 | ✅ 达标（2026-11-17）：美颜开+检测关 30.2fps / CPU 30–32% / 美颜 0.78–0.94 ms；demo 全开（含检测与分屏）30.0fps，CPU 115–123% 主要由 M2 检测贡献（见 BOARD §5.2） |
| A3 | 美颜效果明显，背景/头发不受影响，无接缝 | 对比截图，人工检查 | ✅ 达标（2026-11-17）：同帧分屏 `docs/evidence/m3-split-demo.png`、近景放大 `m3-split-closeup.png`、遮罩预览 `m3-mask.png`；皱纹/色斑平滑、眼睛眉毛保留、遮罩外背景头发无处理、羽化无接缝 |
| A4 | 正脸与 ≤45° 侧脸可检出，≥3 张脸 | 固定测试素材，逐条勾选 |
| A5 | F1–F10 均可用，连续播放 1h 无泄漏 | 演示流程 + `free`/句柄检查 | 未做长跑（M4 补测）；M3 期间反复启停 + 快照 20 余次均 rc=0 |
| A6 | （延期，本期不验收）HLS 与 RTSP 流可播放 | 随 F2 移出本期 |

## 8. 依赖与风险

- 依赖：板端 `mppvideodec`/`gtk4paintablesink`/`librknnrt`/`librga` 可用（2026-11-14 审计通过）；
  有一张 RetinaFace/SCRFD RKNN 模型；有含人脸的测试素材（用户提供的公司自有素材）。
- 主要风险与降级方案见设计文档“风险与降级”章节，M1/M3 实测后回填 [BOARD.md](BOARD.md)。
- 若 NPU 不可用：仅保留硬解播放，美颜开关置灰，不影响演示主线。
