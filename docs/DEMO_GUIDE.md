# 演示指南（草稿）

> 状态：M1 已实现并在板端验证（2026-11-14，1080p30 实时）；M2 检测与 M3 美颜待做，本文件随后续里程碑据实修订。演示范围（2026-11-14 确认）：本地硬解播放 + 自动美颜 + 一键/分屏对比；网络流与字幕不在本期。
> 环境与性能前置条件见 [BOARD.md](BOARD.md)，范围见 [PRD.md](PRD.md)。

## 1. 演示目标

用一段人像视频，在一次演示中同时说明三件事：

1. 视频由 **VPU 硬解**（画面流畅、CPU 占用低）；
2. 人脸被 **NPU 自动检测**，磨皮/美白只作用在脸部区域（背景、头发保持原样）；
3. 一键切换 **原图/美颜对比**，效果肉眼可辨，并能看到实时的 fps 与 NPU 耗时。

## 3. 演示步骤（草稿，M3 后修订）

1. **启动**：执行
   `python3 scripts/launch_player.py --demo <媒体路径>`，窗口出现在 DSI 屏上
   （桌面启动器在 M4 提供）。
2. **硬解播放**：播放 1080p30 H.264 人像视频，全屏；指出信息面板的
   `decode=mppvideodec (HW)`、分辨率、`fps ≈ 30`，说明色彩转换走 GPU、CPU 约 16%。
3. **自动美颜**：默认开启美颜，画面中人物脸部平滑/提亮；移出画面或遮挡脸部，
   指出“无人脸时不处理”，背景与头发保持原样（A3）。
4. **强度调节**：拖动磨皮/美白滑杆，说明强度 0–100 与实时生效；强调只处理
   人脸区域、羽化蒙版无接缝。
5. **一键对比**：按 Compare（或分屏）切换原图/美颜，效果差异放在同一帧上对比（F9）。
6. **信息面板**：读数 `fps`、`NPU inference ms`，给出 A2（≥25fps）结论。
7. **多人/侧脸**：播放多人素材，说明最多 3 张脸、≤45° 侧脸仍可检出（A4）。
8. **收尾（可选）**：连续播放 1h 稳定性（A5），或 P1 预览（瘦脸/大眼，若实现）。

## 4. 讲解要点

- 不是“软件滤镜”：解码、检测、美颜分别落在 VPU、NPU、GPU，CPU 只做调度，
  这是 RK3576 相对纯 CPU 方案的核心价值。
- 参考项目定位：IINA 是桌面播放器交互的标杆，ExoPlayer 是“解码 + 渲染可插拔”
  的分层参考；M2 版本用 GStreamer 还原同样的分层（source → decode → filter →
  sink），美颜就是一个可插拔的 filter。
- 自动美颜的边界：先检测再处理，检测按帧间隔降低开销，帧间用“上次结果/跟踪”
  补足；无人脸时整条美颜链路透传。
- 效果与性能的折中：磨皮/美白强度、检测间隔、处理分辨率都是可调参数，
  演示时可以指出当前档位与实测 fps。

## 5. 降级预案

| 情况 | 预案 |
|------|------|
| NPU 模型/运行时异常 | 关闭美颜，演示硬解播放与信息面板；说明美颜为 M3 目标并展示对比图 |
| 美颜帧率不足 | 降低检测频率、切 720p 处理档（信息面板显示实际值） |
| `gtk4paintablesink` 异常（已验证 0.13.5 可用，留作预案） | 用独立全屏 `waylandsink` 窗口，对比模式改为前后切换而非分屏 |
| 4K 素材缺失或播放不流畅 | 4K 不作硬指标（P4），改用 1080p H.265 展示硬解余量 |
| 摄像头输入 | 本期不做（P2 结论），无需准备 |
| 素材版权问题 | 只用公司自有素材；不下载影视片段做演示 |
